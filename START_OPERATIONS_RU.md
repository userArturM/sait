# Обновление «Чистая вода»: кабинет, доставка и обслуживание

Редакция 2026-10-23.2. Это обновление исходников для PHP-хостинга. На рабочий сервер оно автоматически не устанавливалось. Старые заказы, пользователи и настройки хранятся вне сайта и не заменяются seed-файлом.

## Что добавлено

- Запрос удаления кабинета с проверкой пароля; план очистки до применения; очистка контактных данных завершённых оплаченных заказов через 30 дней, если нет правового удержания.
- Закрытое хранилище erasure.json запрещает возврат удалённых данных при восстановлении старой копии. Очистка затрагивает управляемые JSON-копии, а финансовые суммы и остатки остаются неизменными.
- Задачи очистки внешних CSV, почты и Water19 с ручной отметкой результата. Программа не может удалить скачанные файлы на чужих компьютерах.
- SMS.RU: одноразовые коды с хешированием, сроком 5 минут, 5 попытками, привязкой к сеансу и назначению, задержкой 60 секунд, лимитом 3 запроса на номер в час и общим лимитом 30 в сутки. SMS-восстановление возможно только для ранее подтверждённого номера. При отключённом SMS регистрация остаётся доступной, но номер не считается подтверждённым.
- Смена пароля с завершением остальных сеансов, история статусов и согласованное время доставки в кабинете.
- Структурированный выбор населённого пункта, проверка улицы/номера дома и противоречия между выбранным пунктом и адресом; пересчёт цены/минимума до отправки.
- Очередь уведомлений продавцу и на необязательный e-mail покупателя, повторные попытки с задержкой, напоминание продавцу и предупреждение в панели о новых заказах старше 15 минут.
- Полная копия данных, загруженных фотографий, принятых редакций документов и реестра удаления с контрольными суммами; проверка и восстановление через CLI.

## Установка

1. Сохраните резервную копию действующего сайта и закрытого каталога данных средствами хостинга.
2. Замените файлы из архива. Сохраните существующий backend/config.php, закрытое хранилище, свои фото assets/uploads и архив legal. Не копируйте тестовые данные на рабочий сервер.
3. Требуется PHP 8.1+ (проверено на 8.3), JSON, sessions, ctype, fileinfo; для SMS нужен HTTPS-доступ PHP к sms.ru и allow_url_fopen. Для почты настройте mail() на хостинге.
4. В панели появится раздел «Обслуживание». Сначала просмотрите план удаления. Старые завершённые заказы без достоверной даты завершения показываются для ручной проверки и автоматически не очищаются. Основания удержания указываются в карточках заказов, их нужно пересматривать после разрешения претензий.
5. Проверьте весь путь заказа на собственном домене. Убедитесь, что письма приходят на ваш тестовый адрес, прежде чем включать почту для покупателей.

## SMS и почта

В существующий массив backend/config.php добавьте только нужные ключи, не заменяя прочие настройки:

```php
'sms_enabled' => true,
'sms_api_id' => 'ВАШ_API_ID_SMS_RU',
'sms_daily_limit' => 30,
'mail_enabled' => true,
'mail_from' => 'АДРЕС_НА_ВАШЕМ_ДОМЕНЕ',
'mail_to' => 'ВАШ_АДРЕС_ПРИЁМА_ЗАКАЗОВ',
```

Секреты не добавлять в общедоступные файлы, ZIP или Git. Нужен реальный договор/аккаунт SMS.RU, баланс и разрешённый отправитель у провайдера. При недоступности провайдера код не считается отправленным и подтверждение не обходится. Проверить доставку на принадлежащем вам телефоне. Ограничить расходы также на стороне провайдера. API: https://sms.ru/api/send .

Почта: настроить отправителя на хостинге, SPF/DKIM/DMARC по инструкциям вашего провайдера. Статус `sent` означает принятие почтовой системой PHP, а не прочтение/доставку. При неопределённом сбое после принятия письма повтор может привести к повторному сообщению; один и тот же Message-ID помогает почтовой системе распознать повтор. Новый заказ при повторе уведомления не создаётся. После пяти неудач задача требует ручного повтора из панели. Без cron очередь не обрабатывается непрерывно.

## Фоновые задания (cron на хостинге)

Замените пути ниже на путь к PHP и сайту из панели REG.RU. Это примеры, не готовые пути вашего аккаунта:

```cron
* * * * * /ПУТЬ/php /ПУТЬ/САЙТ/backend/manage.php notifications
*/5 * * * * /ПУТЬ/php /ПУТЬ/САЙТ/backend/manage.php maintenance --apply
```

Сначала выполнить `maintenance` без `--apply` и проверить план. По включении cron очистка необратима: обычное восстановление сохраняет реестр уже удалённых данных. Активные заказы, долги и обоснованно удержанные сведения не очищаются этим процессом. Реестр удаления нельзя заменять старой копией. Последний отчёт — `last-erasure-report.json` в закрытом хранилище; для подтверждения уничтожения владелец оформляет необходимые документы по фактическому выполнению, включая внешние системы. Логи веб-сервера, поставщика SMS/почты и аналитики настраиваются отдельно.

## Проверка и восстановление

```bash
php backend/manage.php full-backup
php backend/manage.php verify-backup /АБСОЛЮТНЫЙ/ПУТЬ/копия.json
php backend/manage.php restore-full /АБСОЛЮТНЫЙ/ПУТЬ/копия.json
php backend/manage.php restore-full /АБСОЛЮТНЫЙ/ПУТЬ/копия.json --apply
```

Команда без `--apply` только проверяет. Перед применением отключить приём новых заказов в панели, включить режим обслуживания домена на хостинге и остановить фоновые задания на время восстановления. Само восстановление защищено общим файловым lock; файлы сначала проверяются, конфликт существующего содержимого отклоняется. После восстановления заказы остаются приостановленными, пользовательские сеансы сбрасываются, незавершённые уведомления не отправляются автоматически. Вручную проверить финансы/остатки, очередь и затем включить приём заказов и cron.

В копию входят данные пользователей (включая хеши), настройки сайта, заказы/оплаты, склад, фотографии uploads, архивы документов и реестр удаления. **Код сайта, серверный config.php, ключи администратора/интеграции, настройки почтового сервера и сам cron нужно резервировать отдельно средствами хостинга.** Контрольные суммы выявляют повреждение, но не шифруют копию и не удостоверяют доверенный источник. Хранить копии вне публичного каталога.

При переносе на новый сервер нужен самый свежий erasure.json: старая полная копия не знает об удалениях, выполненных после её создания. Сначала восстановить свежий реестр удаления, затем данные. Управляемые копии в закрытом каталоге очищаются; внешние архивы требуют отдельной обработки.

## Ограничения, требующие фактических данных владельца

- SMS, почта и cron поставляются отключёнными/не установленными. Тесты используют заглушку доставки: они не подтверждают доставку реальных сообщений.
- Проверка адреса ограничена выбранным населённым пунктом, наличием дома и известными противоречиями. Нет геокодера и проверки фактического существования дома; оператор уточняет адрес. За пределами трёх пунктов — согласование по телефону.
- Сведения о хостинге, расположении баз, договорах с обработчиками и уведомлении РКН необходимо подтвердить владельцу. РКН не уведомлялся от вашего имени.
- Карточки воды всё ещё требуют фактических сведений с этикеток и документов поставщиков (это отдельный пункт предыдущего аудита).
