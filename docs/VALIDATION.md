## Воспроизведение на отдельной тестовой копии

Не запускайте HTTP/browser тесты против рабочего сайта. Создайте backend/config.php с отдельным data_dir вне сайта и тестового администратора `CW-test-admin-password-2026` через backend/manage.php admin. Этот пароль существует только в тестовой среде; в архиве нет готового администраторского хеша или рабочего пароля.

- `php tests/core_test.php` — логика в памяти.
- `python tests/static_check.py` — ссылки, ID и атрибуты.
- Поднимите PHP `php -S 127.0.0.1:8088 -t .`; в другом окне `python tests/http_test.py`. Для другого адреса задайте CW_TEST_BASE. Тесты пишут синтетические записи в тестовую базу.
- Для браузера установите Playwright в отдельной среде (`npm install playwright`; `npx playwright install chromium`), запустите `node tests/browser_test.cjs` из корня сайта. При необходимости задайте CW_PHP_BINARY и CW_CHROMIUM_PATH. Скрипт сам поднимает сервер на 8094; требуется чистое тестовое хранилище с 13 исходными товарами и тестовым администратором. Установка браузерных зависимостей в архив не включена.
- `python tests/bridge_test.py /path/to/Water19Pro2` — использует core.py оригинальной Water19 в отдельной временной SQLite базе.
- Параллельный сценарий: запустите tests/store_worker.php шесть раз одновременно в отдельной пустой базе; все ответы должны содержать один ID, только один duplicate=false.

Отчёты вывода: core-results.txt, http-results.txt, browser-results.txt, bridge-results.txt, concurrency-results.txt в этой папке. Все цены и товары сверены с исходным ZIP.
