## Обязательные сведения, которые ещё нельзя заполнить достоверно

1. Адрес оператора по фактическим регистрационным данным и необходимые контактные сведения.
2. Конкретная дата начала обработки: плановая дата после готовности и подачи уведомления; не дата создания ZIP и не произвольная задняя дата. Проверьте, не было ли обработки обращений/клиентов вне сайта ранее.
3. ФИО и контактные сведения лица, ответственного за организацию обработки; для ИП без сотрудников это может быть сам предприниматель, если соответствует организации работы.
4. Полное наименование и сведения о контрагенте REG.RU по вашему договору, фактическое местонахождение серверов/баз, страна и адрес размещения; их нельзя выдумать по названию бренда хостинга.
5. Полное наименование другого почтового провайдера, место серверов и условия обработки. В новой форме почта получает только номер заказа, но если реальные обращения по email содержат персональные данные — их обработка остаётся частью деятельности оператора.
6. Фактическое место локальной базы Water19 и резервных носителей, лица с доступом.
7. Наличие/отсутствие и перечень трансграничной передачи с учётом реально используемых провайдеров. Отсутствие автопередачи в мессенджеры не доказывает отсутствие всех трансграничных потоков.
8. Конкретные сроки/условия прекращения обработки и правила уничтожения по каждой цели; отдельно копии, письма, заказы и кабинеты. Код не выполняет автоматическое удаление по сроку: нужен установленный процесс и соответствующая доработка при необходимости.
9. Фактически внедрённые организационные меры и подтверждение соответствия публичных документов реальному процессу.

До запуска также нужны достоверные сведения о товарах/маркировке, применимая организация выдачи чеков и порядок возвратов. Обязательные товарные сведения не следует заменять одной общей фразой «по запросу». В исходных материалах нет состава и изготовителей каждой партии — эти сведения владелец предоставляет по фактическим этикеткам и документам.
