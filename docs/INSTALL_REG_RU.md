# Установка на REG.RU

## До загрузки

1. Сохраните ZIP текущих файлов сайта и резервную копию действующих данных, если они есть. Не перезаписывайте папки с реальными заказами. В предоставленном исходном архиве сервера хранения заказов не было.
2. Убедитесь, что сертификат действует для чистая-вода.site. Этот архив не выдаёт SSL и не исправляет DNS. Не загружайте принудительный HTTPS на хост без рабочего сертификата.
3. В панели хостинга выберите PHP 8.2 или новее, Apache 2.4 с AllowOverride (mod_rewrite/mod_headers). Достаточно стандартных PHP-модулей json, session, openssl, filter; PDO/SQLite для самого сайта не нужны.
4. Узнайте абсолютный путь web-каталога домена и путь приватной папки вне него. В ISPmanager название может отличаться от public_html.

## Загрузка

1. Распакуйте архив. Загрузите файлы корня в папку домена, включая .htaccess. Не загружайте ZIP как страницу сайта.
2. Создайте отдельную папку cw-private рядом с папкой сайта, вне любого web-каталога. Например: `/var/www/LOGIN/data/cw-private`, а сайт `/var/www/LOGIN/data/www/xn----7sbbhku9buj1cwf.site`.
3. PHP-пользователь должен владеть cw-private и иметь запись. Не ставьте 777: используйте 700 для каталогов и 600 для приватных файлов, если на тарифе PHP выполняется от владельца.
4. Скопируйте backend/config.example.php в backend/config.php и укажите реальный абсолютный data_dir. Изначальное значение рассчитано на расположение сайта и может не совпасть с вашим хостингом. Код откажется использовать папку данных внутри сайта.
5. backend/config.php — конфигурация, не место для публичных паролей. Проверьте, что `/backend/seed.json`, `/backend/config.php` и `/integration/` возвращают 403. Если Apache не применяет .htaccess — исправьте конфигурацию хостинга до запуска.

## Создать владельца без SSH

1. В файловом менеджере создайте `cw-private/setup.key` со своим длинным случайным одноразовым ключом, минимум 32 ASCII символа. Не используйте пароль администратора в качестве ключа. Ключ не должен лежать в папке сайта.
2. Откройте `https://чистая-вода.site/setup.php`. Нужен HTTPS с действительным сертификатом.
3. Введите ключ и новый пароль владельца длиной минимум 16 символов дважды. Сохраните пароль в менеджере паролей.
4. После успешной установки setup.key удаляется, повторная установка закрывается. Можно удалить setup.php из веб-каталога.
5. Откройте `/admin.html` и войдите.

Если есть SSH: из папки сайта выполните `php backend/manage.php admin` и введите пароль в STDIN. Пароль не передавайте как аргумент команды. Изменение пароля отзовёт существующие администраторские сеансы.

## Почта

По умолчанию заказ уже сохраняется и виден в панели, но email выключен. Для включения:

- Создайте подтверждённый адрес отправителя на домене и настройте доставку по инструкции хостинга (SPF/DKIM при поддержке).
- В config.php укажите `mail_from` и `mail_enabled => true`; `mail_to` сохранён: internet.list@internet.ru.
- Создайте тестовый заказ, проверьте панель и входящие/спам. `mail_status=sent` означает принятие функцией mail(), не доказательство доставки в ящик.
- При сбое почты заказ сохраняется. В панели есть повтор уведомления. Письмо содержит только ID; для данных покупателя войдите в панель.
- SMTP-библиотека не подключена, это транспорт PHP mail хостинга. Если тариф требует SMTP, нужно добавить поддерживаемый SMTP транспорт с секретами вне сайта.

## Настройка магазина

1. В «Каталог и склад» внесите реальные остатки (или оставьте количественный учёт отключённым), проверьте цены.
2. Установите реальный список интервалов в config.php. При необходимости задайте slot_capacity; лимит общий для доставок в каждый день/интервал, не по населённым пунктам.
3. Сделайте тестовые заказы: Пластуновская 2 бутыли, Динская 3, самовывоз, заказ с новой тарой. Проверьте суммы и адрес.
4. Подтвердите, отправьте в доставку, завершите с фактической оплатой и пустой тарой. Убедитесь, что повторное сохранение доставки не списывает склад ещё раз.
5. Создайте кабинет, сохраните ключ восстановления, адрес, заказ после входа и заявку на регулярную доставку.
6. Проверьте архивную копию и CSV. Тесты на реальных данных не запускайте; тестовые заказы можно отменить до завершения.
7. Уведомление РКН не подано автоматически. Сначала завершите фактические сведения и организационные процедуры — docs/RKN_FIELDS_RU.md.

## Кеш на iPhone

Версия service worker изменена, прежние кеши clean-water удаляются при активации. Обновите страницу, закройте и откройте установленный ярлык. API и кабинеты не кешируются. Если после обновления видна старая форма — очистите данные сайта в настройках Safari и откройте заново.

## Резервирование и восстановление

Перед изменением хранится предыдущая версия state.json. По умолчанию последние 30 копий; это число версий, не число дней. Скачивайте ручные копии из панели на отдельный защищённый носитель.

CLI: `php backend/manage.php backup`. Восстановление: выключите приём сайта на время, затем `php backend/manage.php restore /absolute/backup.json`. Сохраните актуальную копию до восстановления. Восстановление возвращает старую историю целиком, поэтому более новые заказы могут исчезнуть — перед этим сверяйте их отдельно. Не заменяйте активный state.json через браузерный файловый менеджер во время приёма заказов.

При откате сайта на старую версию сохраните cw-private. Старый send-order.php не умеет обрабатывать новые данные; требуется согласованный откат файлов и режима приёма заявок.


## Обновление 3.0 / 3.0.1 → 3.1

1. Сделайте копию файлов сайта и приватной папки с реальными данными. Временно ограничьте доступ средствами хостинга.
2. Замените публичные файлы, включая app.js, admin.js, admin-extensions.js, CSS, api.php, backend/core.php и новый backend/catalog_admin.php. Загрузите .htaccess всех папок.
3. Сохраните существующий backend/config.php и весь cw-private; их нет в поставке. Не запускайте повторную первоначальную настройку владельца и не заменяйте state.json на seed.json. Схема данных совместима: новые настройки получают значения по умолчанию, поля карточек добавляются при сохранении.
4. Сохраните уже загруженные изображения. Создайте assets/uploads и разрешите PHP запись только в этот каталог для фото (обычно 755/775 с правильным владельцем, не 777). Код сайта и backend не должны быть общедоступными для записи. Проверьте getimagesizefromstring, memory_limit не менее 64 МБ, post_max_size не менее 6 МБ и ограничения веб-сервера. Загрузка идёт JSON; предел приложения — 3 МБ исходного фото.
5. Для рабочей правки 3.1 начните с docs/ADMIN_3_1_RU.md. Проверьте вход, загрузку фото, сохранение товара, объявление, паузу/возобновление и тестовый заказ. Затем проверьте почту, права приватных папок, SSL и .htaccess на REG.RU. Они не проверены локальным PHP-сервером.
6. Обновите страницу: изменён ключ service worker. При проблемах со старым интерфейсом очистите данные сайта. Не удаляйте приватную папку.
7. JSON из панели не содержит фото и архива принятых HTML документов: дополнительно резервируйте assets/uploads и cw-private/legal, а также настройки и пароль администратора.
